## Project Overview

**RuleC** is a domain-specific language (DSL) designed for expressing IoT sensor trigger rules. The compiler translates human-readable `.rc` rule files through a full compilation pipeline into portable, zero-heap-allocation C99 code that can run on resource-constrained microcontrollers.

### Compilation Pipeline

```
.rc source
   │
   ▼
[1] Lexer          — tokenises keywords, identifiers, literals, operators
   │
   ▼
[2] Parser         — recursive-descent → AST (Program, Rule, BinOp, Comparison, Action)
   │
   ▼
[3] Semantic Analyzer — symbol table, type checks, undeclared sensors, contradiction detection
   │
   ▼
[4] Code Generator — emits evaluate_rules.c + evaluate_rules.h (C99)
   │
   ▼
evaluate_rules()   — compiled into the target application via gcc
```

## RuleC Grammar (BNF)

```
Program         ::= ( Declaration | Rule )* EOF
Declaration     ::= "SENSOR" IDENTIFIER ":" Type ";"
Type            ::= "float" | "int" | "bool"
Rule            ::= "RULE" IDENTIFIER ":" "IF" Condition "THEN" ActionList ";"
Condition       ::= LogicalOr
LogicalOr       ::= LogicalAnd ( "OR" LogicalAnd )*
LogicalAnd      ::= PrimaryCond ( "AND" PrimaryCond )*
PrimaryCond     ::= IDENTIFIER RelOp Literal
                  | "(" Condition ")"
                  | "NOT" PrimaryCond
RelOp           ::= ">" | "<" | ">=" | "<=" | "==" | "!="
ActionList      ::= Action ( "," Action )*
Action          ::= IDENTIFIER "(" ( Literal | IDENTIFIER )? ")"
Literal         ::= NUMBER | STRING_LITERAL | IDENTIFIER
```

## Quick Start

### Requirements
- Python 3 (no external packages)
- `gcc` (C99-compatible)
- `make` (optional, for convenience)

### Build & Run

```bash
# Option A — via Makefile (recommended)
make          # compiles overheat.rc → evaluate_rules.c/.h, then builds rulec_demo
make test     # runs the full test suite (5 harness cases + error detection)
make clean    # removes generated files and binary

# Option B — manual steps
python3 compiler.py overheat.rc -o .
gcc -Wall -Wextra -std=c99 -o rulec_demo test_harness.c evaluate_rules.c
./rulec_demo
```

### Semantic Error Demo

```bash
python3 compiler.py bad_contradiction.rc -o /tmp/bad_out
# Output: COMPILE ERROR: Rule 'impossible_rule': contradictory condition on 'temp' ...
```

## Semantic Checks Implemented

| Check | Example |
|-------|---------|
| Undeclared sensor | Using `pressure` without `SENSOR pressure: float;` |
| Duplicate sensor declaration | Declaring `temp` twice |
| Duplicate rule name | Two rules with same name |
| Type mismatch | Using `>` on a `bool` sensor |
| Contradiction detection | `temp > 30.0 AND temp < 10.0` (unreachable rule) |
| Unknown action | Calling `beep()` (not in known-actions set) |
| Wrong argument count | `alert()` with 0 or 2 args |
